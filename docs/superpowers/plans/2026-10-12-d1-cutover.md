# D1 Cutover (3c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Flip production from Supabase to D1 login + data API, with config import rehearsal, a staff-account checklist, walkthrough verify fix, documented rollback, and Supabase removal as a later commit set.

**Architecture:** Keep the existing D1 auth and `/api/data/*` stack. Cutover is mostly ops + one deploy env change; code changes are limited to the walkthrough selector, any import-script mismatch fixes, CLAUDE.md / walkthrough docs, and (after live confirmation) deleting Supabase paths.

**Tech Stack:** Cloudflare Worker + D1, Vite `VITE_DATA_SOURCE`, GitHub Actions deploy, Playwright walkthrough, existing `d1-import-config.mjs`.

## Global Constraints

- Branch `feat/d1-cutover` only. Never merge or push to `main` (Glen merges).
- Never run `--remote` or `wrangler d1 create`.
- Never write passwords, tokens or keys into chat, code, docs or commits.
- Don't create BACC staff accounts until Glen says it is D1 day.
- Tests first for any fix. `npm test` stays at 0 failing.
- SQL in store files; permissions in pure rules; real migrations via `tests/helpers/sqliteD1.js`.
- Spec outranks this plan. Avatars: off for the pilot (later add-on). Cutover-day
  order is binding: remote import → admin+staff on D1 → flip → live check.
  Rollback is clean only until staff file on D1.
